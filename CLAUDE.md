# Code Royale Bot — контекст проекта (handoff для Claude Code)

Этот файл — полный контекст проекта. Положи его в корень репозитория (можно переименовать в `CLAUDE.md`, чтобы Claude Code читал его автоматически).

## Цель

Самый успешный бот для CodinGame **Code Royale** (раздел Bot Programming): пройти лиги Wood → Bronze → Silver → Gold → Legend, затем гонка за топ лидерборда.

## Формат работы (важно)

- Пользователь (Andrey) руководит, Claude делает и **перед каждым этапом расписывает, что и зачем будет сделано, понятным языком** (он C#-разработчик, но экосистему CodinGame не знает).
- В этом проекте подробные объяснения приветствуются — это осознанное исключение из его обычного «пиши компактно».
- Обращение на «ты».
- Двигаемся поэтапно: разложили этап → «делай» → сделали → следующий.

## Принятые решения

1. **Язык: C#**, порт симулятора+поиска в C++ — только если реально упрёмся в CPU на этапе гонки за топ.
2. **Пропускаем этап «умной эвристики»**: расходный примитивный бот (~50 строк) только чтобы выйти из Wood в Bronze и служить спарринг-партнёром; вся реальная работа сразу в симулятор + поиск.
3. Архитектура целевого бота (по образцу победителей контеста):
   - точный симулятор движка (порт открытого рефери 1-в-1, бит-в-бит, без аллокаций);
   - beam search для действий королевы (глубина 10–15, ширина 25–50, 8 направлений + BUILD-действия; противник моделируется почти статичным);
   - eval: своё HP (большой вес) − HP врага/10; башни через (недостающее HP)²; доход шахт; штраф за <1 или >3 казарм; близость казарм к врагу; случайный тай-брейк;
   - макро (что тренировать) — отдельной простой эвристикой, не поиском (так делал и победитель).
4. Все изменения принимаются **только по статистике локальной арены** (сотни игр), не «на глаз».

## Правила игры (шпаргалка, сверено с исходниками рефери)

- Карта 1920×1000, 200 ходов, лимит **50 мс/ход** (первый ход ~1000 мс). Победа: убить королеву врага или больше HP на 200-м ходу.
- Королева: 100 HP, скорость 60/ход, радиус 30. Касается сайта → строит. Касанием сносит вражеские шахты и казармы (башни — нет).
- Ввод/вывод: каждый ход читаем состояние из stdin, печатаем 2 строки: `MOVE x y | BUILD id TYPE | WAIT` и `TRAIN [id...]`.
- Сайты (12–24 на карте, симметрично). Постройки:
  - **Шахта** (MINE): доход +incomeRate/ход, повторный BUILD апгрейдит до maxMineSize сайта; золото в сайте конечное, кончилось → шахта исчезает.
  - **Башня** (TOWER): 200 HP при постройке, повторный BUILD +100, максимум 800; радиус растёт с HP (площадь покрытия = HP × 1000 + площадь сайта); тает −4 HP/ход; бьёт ближайшего вражеского крипа в радиусе, иначе королеву; урон больше вблизи (мин. 1 по королеве, мин. 3 по крипам, +1 за каждые 200 ед. недолёта до края радиуса).
  - **Казарма** (BARRACKS-KNIGHT/ARCHER/GIANT).
- Юниты (все теряют 1 HP/ход и умирают сами):
  - **Рыцари**: 80 g → 4 шт., скорость 100, HP 30, бегут к вражеской королеве, 1 урона за касание; тренировка 5 ходов.
  - **Лучники**: 100 g → 2 шт., скорость 75, HP 45, дальность 200, урон 2 (10 по гигантам); бьют только крипов, королеву не трогают (чистая оборона); 8 ходов.
  - **Гиганты**: 140 g → 1 шт., скорость 50, HP 200, идут к ближайшей вражеской башне, 80 урона за удар; 10 ходов.
- Порядок хода в движке: действия игроков → движение/бой крипов (коллизии в 5 подшагов!) → действия построек → доход → смерть крипов → проверка конца. Порядок и округления критичны для точности симулятора.
- **Wood-лиги играют по урезанным правилам** (фиксированный доход +10, часть построек отключена); полные правила — с Bronze. До Bronze не переусложнять.

## Что выигрывает (выжимка постмортемов топов контеста)

- Весь топ = точный симулятор + поиск для королевы: RoboStac (1-е) — beam search до глубины 15, ~8000 симуляций/ход; Agade (3-е) — simulated annealing глубиной 7; IloIlo (4-е) — генетика 10–14. Чистые эвристики в топ не попали.
- Королева — 90% игры: кайтинг от рыцарей, заходы мимо башен. Это даёт только поиск.
- Мета: рыцарский раш на стартовые 100 g (открытие Agade: 2 шахты + казарма + волна) + экономика на шахтах + оборона башнями; **гиганты — ответ на башенные крепости**; лучники почти бесполезны.
- Противника моделировать почти не нужно («вражеская королева мало что может сделать» — RoboStac).
- Главный урок всех топов: **точность симулятора** (тест: на реальных реплеях предсказывать следующее состояние) и локальное тестирование статистикой.

## План этапов и статус

- [ ] **Этап 1 — инфраструктура**: C#-проект + скрипт склейки в один файл (CG принимает только один файл, вставка в браузере вручную); расходный Wood-бот; сборка локального рефери (Kotlin/JVM, репо csj/code-royale); арена self-play (cg-brutaltester и/или psyleague); выход в Bronze. Оценка 1–2 сессии.
- [ ] **Этап 2 — симулятор**: порт рефери 1-в-1 на C#, тесты точности на реплеях (совпадение состояний бит-в-бит).
- [ ] **Этап 3 — beam search + базовый eval** → Silver/Gold.
- [ ] **Этап 4 — тюнинг** eval и макро через self-play и CGBenchmark → Legend.
- [ ] **Этап 5 — гонка за топ**: разбор реплеев конкретных противников, подстройка; при нехватке CPU — порт в C++.

## Лиги (`Referee.init`, по `gameManager.leagueLevel`)

| Лига | Уровень | Шахты | Башни | Гиганты | Доход | Сайтов | HP королевы |
|---|---|---|---|---|---|---|---|
| Wood 3 | 1 | нет | нет | нет | фикс. +10/ход | 2×(6..12) | 100 |
| Wood 2 | 2 | нет | да | да | фикс. +10/ход | 2×(6..12) | 100 |
| Wood 1 | 3 | да | да | да | только шахты | 24 | 100 |
| Bronze+ | ≥4 | да | да | да | только шахты | 24 | **случайно 25..100 с шагом 5, одинаковое у обоих** |

- **BUILD типа, отключённого в лиге** (TOWER/MINE/BARRACKS-GIANT в Wood 3, MINE в Wood 2) = `PlayerInputException` = **бот убит**. Лига из ввода не определяется → задавать константой перед сабмитом (сабмит ручной).
- HP королевы читать из ввода на первом ходу (health своей королевы). Постмортемы контеста писались при 100 HP — дебюты оттуда проверять по реплеям арены.
- Золото на карте конечно: 24 сайта × 200..350. Сайты парами, центрально-симметричные, радиус 60..90, золото 200..250, размер шахты 1..3; ближе 500 к центру +50 золота и +1 к размеру, ближе 200 — ещё +50/+1 (до 5).

## Ввод/вывод

- Старт: `numSites`, затем `siteId x y radius`. Ход: `gold touchedSite`; по каждому сайту `siteId gold maxMineSize structureType owner param1 param2`; `numUnits`; `x y owner unitType health`.
- `unitType`: −1 королева, 0 рыцарь, 1 лучник, 2 гигант. `structureType`: −1 пусто, 0 шахта, 1 башня, 2 казарма. `owner`: −1 ничей, 0 мой, 1 чужой.
- Шахта: `param1` = доход (−1 если не видно), `param2` = −1. Башня: `param1` = HP, `param2` = радиус атаки. Казарма: `param1` = ходов до конца тренировки (0 — простаивает), `param2` = тип крипа.
- **Видимость**: `gold` и `maxMineSize` сайта показываются, только если постройка моя или сайт ближе 300 (`QUEEN_VISION`) к моей королеве, иначе −1. Доход чужой шахты тоже −1 без видимости. **Золото противника не даётся** — вести счётчик: 100 на старте + видимые доходы − замеченные тренировки.
- Порядок юнитов во вводе: крипы игрока 0 в порядке спавна, его королева, крипы игрока 1, его королева. Этот порядок нужен симулятору (см. коллизии).
- Вывод: строка 1 `WAIT` | `MOVE x y` | `BUILD id TYPE` (TYPE: `MINE`, `TOWER`, `BARRACKS-KNIGHT`, `BARRACKS-ARCHER`, `BARRACKS-GIANT`); строка 2 `TRAIN [id ...]`. Лишний токен, двойной пробел, незнакомая команда, несуществующий id — **бот убит**.
- `TRAIN`: повтор id, чужая/не казарма, тренирующаяся казарма, сумма стоимости > золота — warning, **весь TRAIN отклонён целиком**, золото не списывается.
- `BUILD id TYPE`: если королева касается сайта (dist < 30 + r + 5) — постройка планируется; **иначе это MOVE к центру сайта** (удобно как «иди и строй», постройка случится на следующем ходу после подхода).
- Строить на чужой постройке **нельзя** (warning). Касание королевой сносит чужую шахту/казарму (не башню) на фазе крипов того же хода → строить можно со следующего хода. Перестройка своей тренирующейся казармы — warning. Своя простаивающая постройка заменяется чем угодно; MINE на своей шахте = +1 доход до `maxMineSize`, TOWER на своей башне = +100 HP до 800.
- Обе королевы строят на одном сайте в один ход → выполняется одна, по чётности хода (`removeAt(turn % 2)`).
- `touchedSite` — `singleOrNull`: при касании двух сайтов сразу −1, но BUILD проверяется по дистанции и работает.
- Время: 1000 мс первый ход, 50 мс остальные. 200 ходов; конец — смерть королевы или сравнение HP, **при равенстве ничья**; убитый за ошибку бот получает −1.

## Порядок хода (`Referee.gameTurn`) — симулятор копировать построчно

1. `goldPerTurn = 0`, отправка состояния, чтение двух строк.
2. Действия игроков (сначала игрок 0, потом 1): **сначала TRAIN** (списание, `progress = 0`, `isTraining`), **потом команда королевы** — MOVE/BUILD-подход сразу двигает королеву на ≤ 60 без проверки коллизий; постройки откладываются и выполняются после обоих игроков.
3. Крипы: общий список, **стабильно отсортирован по типу** (KNIGHT, ARCHER, GIANT; внутри типа — порядок ввода). `repeat(5)`: каждый крип `move(1/5)`, затем **одна** итерация `collisionCheck` по всем сущностям. Затем `dealDamage` всех крипов; **любой чужой крип** (и лучник, и гигант), касающийся своего ближайшего сайта, сносит на нём чужую шахту; всем крипам −1 HP; королевы сносят чужие шахты/казармы на своём ближайшем сайте в касании.
4. Постройки `act()` в порядке сайтов: **шахта** — доход `min(rate, gold)` в тот же ход, при `gold ≤ 0` исчезает; **башня** — цель: ближайший чужой крип, если dist до центра < `attackRadius`, иначе чужая королева, если в радиусе; потом `health −= 4`, `attackRadius = (int)sqrt((health·1000 + π·r²)/π)`, при `health ≤ 0` исчезает; **казарма** — `progress++`, при `progress == buildTime` спавн (см. ниже).
5. Фиксированный доход (только Wood).
6. Удаление крипов с `health == 0` — **после башен**: крип, умерший от «−1 в ход», в этот ход ещё цель для башни.
7. Проверка смерти королев, конец игры.
8. **Все координаты округляются до целых** (`snapToIntegers`, round half up = `Math.round`). Поэтому ход начинается ровно из состояния во вводе и бит-в-бит достижим; внутри хода — double. Исключение — первый ход: стартовые позиции королев (200,200) и (1720,800) после расталкивания сайтами не округлены, во вводе округлены.

## Формулы (`Characters.kt`, `Structures.kt`, `MapBuilding.kt`)

- `towards(target, d)`: если `dist < d` → `target`, иначе `loc + (target − loc).normalized · d`, где `normalized = (x/len, y/len)`, `len = sqrt(x²+y²)`; при `len < 1e-6` → `(1, 0)`. Сравнения дистанций — по квадратам.
- Свежепостроенная **башня**: `attackRadius = 0` → в ход постройки не стреляет, к следующему ходу HP 196. Урон: `shot = dist(центр) − r_сайта`, `damage = min + (int)((attackRadius − shot) / 200)`, min 3 крипу, 1 королеве.
- **Рыцарь** (r 20, масса 400, HP 30, скорость 100): если dist до чужой королевы > 20 + 30 → шаг к точке `королева + (я − королева).resizedTo(3)`; урон 1, если dist < 20 + 30 + 5.
- **Лучник** (r 25, масса 900, HP 45, скорость 75, дальность 200): цель — ближайший чужой крип, без цели идёт к **своей** королеве; стреляет, если dist < 25 + r_цели + 200 + 5; урон 2, гиганту 10. Королеву не бьёт.
- **Гигант** (r 40, масса 2000, HP 200, скорость 50): идёт к ближайшей чужой башне, **без башен стоит на месте**; бьёт **первую по порядку сайтов** (не ближайшую) чужую башню в касании (dist < 40 + r + 5), −80 HP.
- **Спавн**: позиция казармы + `(±i, ±i)` для i-го крипа (знак: игрок 0 плюс, игрок 1 минус), затем `towards(чужая королева, 30)`, затем полное расталкивание (до 999 итераций). Спавн в фазе построек → в ход спавна крипы не ходят.
- **Коллизии** (`collisionCheck`): список сущностей = крипы игрока 0, крипы игрока 1, королева 0, королева 1, сайты по id. Для каждого `u1` по порядку: сначала кламп в карту 1920×1000 (сайты с отступом 90 + r, юниты — r), затем для каждого `u2 ≠ u1` по порядку с **уже сдвинутыми** координатами: `overlap = r1 + r2 − dist`; если `> 1e-6`: доли сдвига `d1 = m2/(m1+m2)`, `d2 = m1/(m1+m2)`; сайт (масса 0) не двигается, второй берёт весь overlap; `u1 −= dir·(d1·overlap + gap)`, `u2 += dir·(d2·overlap + gap)`, `gap = 1` (0 для стороны сайта). Массы: королева 10000 (её толкают рыцари!), рыцарь 400, лучник 900, гигант 2000.
- Округление Kotlin `roundToInt` = половина вверх; в C# `Math.Round` банковское → использовать `Math.Floor(x + 0.5)`.

## Предложения Claude к плану (не приняты, обсудить перед этапом 1)

1. Арена self-play на C# поверх своего же симулятора (симулятор = арбитр), а не cg-brutaltester: тысячи партий/мин. Kotlin-рефери — только для сверки; его сборка требует Maven Central, Kotlin 1.2.10 и SDK CodinGame 1.30, в песочнице может не собраться.
2. Сверка симулятора без сборки рефери: (а) реплеи арены; (б) **самопроверка в бою** — бот предсказывает следующее состояние и сравнивает с реальным вводом, расхождения в stderr.
3. Wood-бот не расходный: парсер, вывод, тайминг и склейка — каркас настоящего бота, меняется только политика. Константа лиги в коде.
4. В beam search кроме 8 направлений — макро-действия «идти к сайту X и строить Y». Модель противника: королева статична, казармы продолжают тренировать (прогресс виден), башни стреляют, золото противника по счётчику.
5. Оценка и макро зависят от HP королевы (25 vs 100 — разные игры).
6. Горячее место симулятора — расталкивание (5 подшагов × все пары): отсекать заведомо далёкие пары дешёвой проверкой, порядок обработки сохранять, тогда точность не теряется.
7. Порядок этапов оставить, сборку рефери сдвинуть в конец как необязательную.
